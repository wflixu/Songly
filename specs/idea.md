
# 乐遇 Songly

> **遇见音乐，遇见喜欢**
> 英文名：**Songly**
> 一句话定位：Apple Music 曲库很好，推荐不行。苹果的 AI 歌单国行用不了——乐遇来帮你解决。

---

## 1. 缘起 & 用户故事

### 我的真实场景

我是 Apple Music 付费用户（国区）。苹果曲库全、无广告、体验好，但 **个人推荐太弱，歌单容易听腻**。相反网易云音乐的"心动"Tab 推荐很懂我，刷着像短视频一样爽。但网易云广告太多，我不想付两份会员。

我想要：**把网易云那种"每天刷不腻"的推荐体验，搬到 Apple Music 里。**

### 发现的机会

iOS 26.4 苹果推出了 **Playlist Playground**，号称用 AI 生成歌单。但它：
1. **国行用不了** — 依赖 Apple Intelligence，墙内不可用
2. **不读你的听歌历史** — 每次要手动写 prompt
3. **推荐质量差** — Reddit/ZDNet 评测说"生成的都是热门金曲大杂烩"

> 苹果自己做不到的事，我来做。

## 3. 核心功能

### 3.1 MVP 阶段（验证期）

> **目标：验证 LLM 生成的歌单是否真的好听。** 只做最精简的功能闭环，不做商业化，不优化体验。

#### 核心闭环（MVP 范围）

```
MusicKit 读取用户收藏/曲库
        ↓
LLM（DeepSeek/通义千问）分析口味 → 生成推荐
        ↓
MusicKit 搜索 Apple Music 曲库找歌
        ↓
创建播放列表 → 用户打开 Apple Music 听
```

#### MVP 功能清单

| 功能 | 说明 | 方式 |
|------|------|------|
| **每日推荐** | 每天早上自动生成一份 20-30 首歌的播放列表 | 后台定时 |
| **想听（快捷选择）** | 用户点预设按钮切换风格（摇滚/纯音乐/爵士等） | 手动触发 |
| **自动保存** | 推荐歌单自动写入 Apple Music | 自动 |
| **推送通知** | 歌单就绪时通知用户 | 系统推送 |

> MVP 阶段**不包含**：策略轮换、用户反馈闭环、推荐历史、自定义输入等。这些在 PMF 验证通过后再做。

### 3.2 PMF 验证后（完整版）

| 追加功能 | 说明 |
|---------|------|
| **策略轮换** | 5-8 种推荐策略每日不同，避免重复感 |
| **想听（文字描述）** | 用户自由输入想听的风格/情绪/场景 |
| **反馈闭环** | 喜欢/不喜欢，影响下轮推荐 |
| **推荐历史** | 查看过去歌单，重新保存

### 推荐策略池（示例）

| 策略 | 说明 |
|------|------|
| **风格探索** | "你最近听了很多电子，来点 UK Garage 的冷门" |
| **年代回溯** | "翻出你2019年收藏的歌，推荐当年同期的遗珠" |
| **艺人关联** | "你收藏了 Radiohead，试试 Thom Yorke 其他项目" |
| **混搭** | "把爵士和 Lo-fi 混在一起，给你周末下午歌单" |
| **纯随机+过滤** | "今天随机探索，排掉你已经收藏过的" |
| **情绪匹配** | "适合周一早晨的轻快歌单" |

每次推荐时，LLM prompt 中注入「上次推荐了哪些歌，这次不要重复」，确保新鲜感。

## 4. 技术方案

### 技术栈

| 层 | 方案 |
|----|------|
| **前端** | SwiftUI（iOS），未来 macOS |
| **音乐数据** | MusicKit Swift Framework |
| **AI 引擎** | DeepSeek API / 通义千问 API / 月之暗面 API（国内可用） |
| **后端（可选）** | 初期无后端，纯客户端。后续可选 n8n + 轻量服务器 |
| **定时任务** | iOS Background Task / App Group 后台刷新 |

### 关键链路

```
1. MusicAuthorization.request() → 用户授权
2. MusicLibraryRequest<Song>() → 获取收藏歌曲
3. 构建 LLM Prompt：
   "用户收藏了以下歌曲：[歌曲列表]
    请推荐 25 首 Apple Music 曲库里的歌，策略：风格探索
    不要推荐以下歌曲：[上次推荐的]"
4. LLM 返回推荐曲目列表（歌名+艺人）
5. MusicCatalogSearchRequest → 在 Apple Music 曲库搜索匹配
6. 去重（排除已收藏）+ 创建播放列表
7. 用户收到通知 → 打开 Apple Music 听
```

### 为什么 MusicKit 够用

- ✅ `MusicLibraryRequest<Song>` — 读用户收藏
- ✅ `MusicCatalogSearchRequest` — 搜索曲库
- ✅ `Playlist` 创建/修改 API — 创建播放列表
- ✅ `ApplicationMusicPlayer` — 可选内嵌播放
- ❌ 不需要下载、不需要离线、不需要绕过订阅

## 5. 竞品分析

| App | 推荐策略 | 个性化 | 每日自动 | 国行可用 |
|-----|---------|--------|---------|---------|
| **PlaylistAI** | prompt 生成 | ❌ 不读曲库 | ❌ 手动 | ✅ |
| **Harmony** | mood 描述 | ❌ 不读曲库 | ❌ 手动 | ✅ |
| **TuneWizard** | 文字/emoji描述 | ❌ 不读曲库 | ❌ 手动 | ✅ |
| **Soundiiz AI** | prompt 生成 | ⚠️ 部分 | ✅ 每日同步 | ⚠️ Web端 |
| **Playlist Playground (苹果)** | prompt 生成 | ❌ 不读历史 | ❌ 手动 | ❌ **国行不可用** |
| **Muse（本项目）** | **曲库驱动+LLM** | ✅ **完全个性化** | ✅ **每日自动** | ✅ **完美支持** |

**核心差异化：** 不是"写 prompt 生成歌单"的工具，而是 **"基于你的品味，每天自动给你一个不一样的好歌单"**。

## 6. MVP 验证标准

> 这是一份**产品设想文档，不是 PRD**。MVP 阶段的核心不是铺功能，而是回答一个问题。

### 核心验证命题

> **LLM 基于用户 Apple Music 收藏生成的歌单，用户觉得好听的频次有多高？**

### 验证方法

| 验证手段 | 说明 |
|---------|------|
| **自己先用** | MVP 出来后你自己每天用，连续用 2 周，记录每次推荐的质量感受 |
| **朋友/小范围内测** | 邀请 5-10 个 Apple Music 用户试用，每天反馈一句"今天的推荐怎么样？" |
| **定性判断** | 不需要大数据，只要 >50% 的推荐被用户觉得"还不错/有惊喜"，就说明方向对了 |

### "值得继续"的信号

- [ ] 自己用了 2 周，至少 60% 的天数觉得推荐有新鲜感
- [ ] 内测用户平均评价 ≥ "还不错"
- [ ] "想听"功能生成的结果不翻车（风格匹配基本准确）
- [ ] MusicKit 搜索匹配准确率 > 80%（LLM 推荐的歌能在 Apple Music 找到）

### "不值得继续"的信号

- [ ] LLM 推荐的都是热门金曲大杂烩，跟 Playlist Playground 一样无聊
- [ ] MusicKit 搜索匹配率太低，经常搜不到推荐的歌
- [ ] 自己用了几天就不想再打开了

> MVP 验证通过后，再回到这份文档继续做商业化设计。如果验证失败，那成本也很低——几天时间 + 几十块钱的 API 调用费。

## 7. 商业模式（PMF 验证后启动）

> ⚠️ 以下内容在 MVP 验证通过后才纳入规划，MVP 阶段不做任何商业化设计。

### 7.1 成本测算（核心依据）

以 **DeepSeek API** 为例（国内可用，性价比极高）：

| 项目 | 估算 |
|------|------|
| 每次推荐 prompt（用户收藏 + 历史去重） | ~800 tokens |
| 每次推荐 output（歌单+艺人） | ~300 tokens |
| DeepSeek 输入价格 | ¥0.001/1K tokens |
| DeepSeek 输出价格 | ¥0.002/1K tokens |
| **每次推荐成本** | **≈ ¥0.0014（1厘4）** |
| **每月30次（每用户）** | **≈ ¥0.042（4分2）** |
| **每年（每用户）** | **≈ ¥0.5（5毛）** |

> **每天不到1分钱。** LLM 调用费用几乎可以忽略——真正贵的是图片生成、视频、多轮长对话，不是这种单次几百 token 的结构化输出。

### 7.2 两种方案对比

#### 方案 A：用户自填 API Key（❌ 不推荐）

| 维度 | 评价 |
|------|------|
| 用户门槛 | ❌ 极高。普通用户不知道什么是 API Key，注册→充值→绑定，每步都在流失 |
| 开发者成本 | ✅ 零 |
| 获客 | ❌ 严重影响。程序员愿意折腾，但 Apple Music 用户不全是程序员 |
| 售后 | ❌ "我填了 Key 为什么不行？"——你还要帮用户排查 API 问题 |

**结论：用户自填 Key 适合开发者工具（如 VS Code 插件），不适合面向大众消费者的 App。**

#### 方案 B：内置 API Key + 免费增值（✅ 推荐）

| 维度 | 评价 |
|------|------|
| 用户门槛 | ✅ 零。打开 App→授权 MusicKit→直接使用 |
| 开发者成本 | ✅ 极低。每用户每年约 5 毛钱 |
| 风险控制 | ✅ 免费版按日限额，防滥用 |

### 7.3 推荐商业模式：免费增值（Freemium）

```
┌─────────────────────────────────────────────────────────┐
│                免费版（吸引用户）                          │
│  · 每日一次推荐（每天早上一份新歌单）                      │
│  · 基础策略池（3种策略轮换）                              │
│  · 想听：限「快捷选择」模式                             │
│  · 频率限制：每用户每天最多 1 次                          │
│  · 我承担 LLM 成本 ≈ 0.04 元/月/用户                      │
│  · 1000 用户 → 40 元/月，完全可以承受                     │
├─────────────────────────────────────────────────────────┤
│                付费版（升级体验）                          │
│  · 每日两次推荐（早晚各一）                                │
│  · 全部策略池（8 种+）                                    │
│  · 想听：支持「文字描述」自由输入                         │
│  · 想听：无次数限制                                       │
│  · 自定义推荐方向（"适合跑步听""下雨天歌单"）               │
│  · 推荐历史回顾与回溯                                     │
│  · 移除品牌标识                                           │
│  · **12 元/年 或 48 元买断**                              │
└─────────────────────────────────────────────────────────┘
```

### 7.4 收益估算

| 指标 | 数值 |
|------|------|
| 付费转化率（保守） | 5% |
| 1000 免费用户 → 50 付费用户 | 50 × 12元 = **600 元/年** |
| 付费版 LLM 成本 | 每个付费用户约 1 元/年（每日两次） |
| 净利润 | 600 - 50 - 服务器 ≈ **500+ 元/年** |
| ROI | **14 倍以上** |

> 核心逻辑：**用极低的 LLM 成本换取用户增长，付费升级靠「更多的推荐次数 + 更强的控制力」，而不是靠卡推荐功能本身。**

## 8. 分阶段规划

### Phase 1 — MVP 验证（1-2 周）

> **目标：跑通核心闭环，验证 LLM 推荐质量。不做商业化，不做优化，只做最简功能。**

- [ ] MusicKit 集成 + 用户授权
- [ ] LLM 推荐链路（读收藏 → 生成推荐 → MusicKit 搜索 → 创建歌单）
- [ ] 每日一次自动推荐
- [ ] "想听"快捷选择入口（预设按钮）
- [ ] 推送通知
- [ ] **自己先用 2 周，评估推荐质量**
- [ ] **邀请 5-10 人内测，收集反馈**

### Phase 2 — PMF 验证后（MVP 通过后启动）

> **目标：验证通过后，补齐体验，加入商业化。**

- 策略轮换多样化（5+ 策略）
- 反馈闭环（喜欢/不喜欢）
- 想听支持文字自由输入
- 推荐历史查看
- 商业模式落地（付费墙 + 买断选项）
- macOS 版本

## 9. 风险与应对

| 风险 | 应对 |
|------|------|
| **Apple 审核：MusicKit 使用限制** | MusicKit 标准授权，App 仅读收藏+创建歌单，合规 |
| **LLM API 成本** | ✅ 极低。每次推荐仅 ≈ 0.0014 元，每用户每年约 5 毛钱，完全可控 |
| **推荐质量不够好** | 持续优化 prompt，增加策略多样性，用户反馈闭环 |
| **苹果未来封杀类似功能** | Playlist Playground 证明苹果在做但做不好，且国行不可用，不会封杀 |
| **用户隐私顾虑** | 曲库数据不上传服务器？可本地 LLM（端侧模型）兜底 |
